### PortWatch request and fields

The successful request used for the Gulf checks was:

```text
https://services9.arcgis.com/weJ1QsnbMYJlCHdG/ArcGIS/rest/services/Daily_Chokepoints_Data/FeatureServer/0/query?where=portid%3D%27chokepoint6%27&outFields=date%2Cportid%2Cportname%2Cn_tanker%2Cn_total%2Ccapacity_tanker%2Ccapacity&returnGeometry=false&orderByFields=date%20DESC&resultRecordCount=2&f=json
```

Change the `portid` filter for the other chokepoints. Relevant fields include `date`, `portid`, `portname`, `n_container`, `n_dry_bulk`, `n_general_cargo`, `n_roro`, `n_tanker`, `n_cargo`, `n_total`, and matching `capacity_*` fields plus `capacity`. The layer reports a 1,000-row maximum per request; page larger history queries. It advertises JSON and file exports including CSV and GeoJSON.

`date` is an ArcGIS `esriFieldTypeDateOnly`, and the item metadata says call dates are UTC. Responses return a calendar string such as `2026-09-27`, not a millisecond epoch. Preserve it as a date-only UTC value; do not convert it through the browser's local timezone. The metadata's `lastEditDate` is a separate millisecond timestamp and is not the observation date.

Primary references: [layer metadata](https://services9.arcgis.com/weJ1QsnbMYJlCHdG/ArcGIS/rest/services/Daily_Chokepoints_Data/FeatureServer/0?f=json), [layer item description and terms](https://www.arcgis.com/sharing/rest/content/items/3da2b9ca97684916b75c4013f95d18ab?f=json), and the [IMF PortWatch portal](https://portwatch.imf.org/).

## Source-selection boundary

Among the candidates above, no public, keyless live global raw-AIS feed for the Middle East was verified. NOAA is geographically unsuitable, Global Fishing Watch requires an account token and is fishing-focused/noncommercial, and Copernicus/EMODnet add other kinds of data. PortWatch is the strongest low-friction addition, but it is an AIS-derived aggregate and should be presented as a separate source series rather than a replacement for AISStream or as independent proof of traffic.
